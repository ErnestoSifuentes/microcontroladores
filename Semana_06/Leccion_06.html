Tres soluciones para un mismo fenómeno

La semana continúa la práctica 2. En el método bloqueante, el programa detecta un posible cambio, espera un intervalo y vuelve a leer. Es sencillo, pero durante esa espera no avanza el programa principal. Si se acumulan otras tareas críticas, la pérdida temporal puede ser importante. En la variante no bloqueante, se guarda el instante del primer cambio, se siguen ejecutando otras tareas y se acepta el cambio sólo después de que el estado permaneció estable un tiempo predefinido.

El método hardware añade una red RC cuya constante de tiempo depende del valor efectivo de la resistencia y la capacitancia. En la práctica se utiliza un capacitor de 100 nF entre P1.1 y GND con una resistencia pull-up interna. El valor real de esa resistencia es variable, por lo que la constante de tiempo calculada es aproximada y debe compararse con las mediciones.

Respuesta exponencial y lectura digital

En una carga RC ideal, la tensión crece exponencialmente hacia la alimentación. La constante τ determina cuánto tarda en responder: después de un tiempo igual a τ, el capacitor ha recorrido alrededor de 63.2 % de la diferencia hacia el valor final. Aun así, el cambio de estado lógico no ocurre necesariamente en ese instante; se produce cuando la señal cruza el umbral real del puerto.

Conviene distinguir el modelo eléctrico del modelo lógico. Si la entrada es activa en bajo, al cerrar el pulsador el capacitor se descarga y la señal cae. Cuando se libera, el pull-up carga el capacitor y el flanco asciende de manera gradual. Un RC mal dimensionado puede generar un flanco demasiado lento o introducir retardos que dificulten la detección de pulsaciones rápidas.

Máquina de estados: FILTRAR antes de ACEPTAR

Un filtro no bloqueante puede mantener dos variables: último nivel observado y último estado aceptado. Cada vez que la lectura cruda cambia, se reinicia una marca temporal. Sólo cuando la lectura permanece estable durante tdeb se actualiza el estado validado. Esta lógica permite atender UART, timers u otras tareas mientras transcurre la espera.

Hay dos requisitos diferentes: no duplicar pulsaciones y no perder pulsaciones genuinas. Si se selecciona una ventana mayor que la pulsación más corta, el filtro suprimirá eventos válidos. Si es menor que el rebote efectivo, persistirán conmutaciones falsas. La selección es un compromiso experimental y depende también de si se exige validar la liberación.

Comparación medible y reporte

Prepare una tabla con el número de eventos detectados para veinte pulsaciones, el tiempo de respuesta y la duración ocupada por retardos. Registre muestras crudas con osciloscopio o analizador lógico; una captura del LED no revela necesariamente todos los rebotes eléctricos. Para comparar, mantenga el mismo pulsador, alimentación, presión y configuración de E/S.

La interpretación debe señalar los límites del modelo: la corriente de fuga del capacitor, las tolerancias y los umbrales de entrada alteran el resultado. La investigación de interrupciones prepara la semana siguiente, donde se atenderán eventos sin sondear constantemente.

Ejemplo: filtrado RC y latencia

Con una resistencia efectiva hipotética de 30 kΩ y un capacitor de 100 nF, la constante de tiempo de primer orden es 3 ms. La carga hacia el valor final alcanza aproximadamente el 63.2 % al transcurrir una constante, y alrededor del 95 % en tres constantes, es decir, cerca de 9 ms. Estos valores no representan automáticamente el tiempo de cruce del umbral de P1.1.

Considere ahora una ventana de confirmación por software de 20 ms. Cuando la lectura cruda cambia, el algoritmo inicia la cuenta, pero sólo acepta el nuevo estado si se mantiene estable durante la ventana completa. Una pulsación que dura 12 ms podría no aceptarse, aunque sea genuina. El experimento debe comprobar simultáneamente supresión de rebotes y pérdida de pulsaciones.

Antirrebote temporal no bloqueante en C

El código siguiente muestra una operación concreta del MSP430G2553. Identifique sus entradas, registros y condiciones iniciales antes de incorporarlo a la práctica.

#include <stdint.h>

/* Entradas: nivel del pulsador (0 = presionado), tiempo en ms.
   Devuelve 1 una sola vez por pulsación validada. */
uint8_t evento_pulsador(uint8_t lectura, uint32_t ms)
{
    static uint8_t ultima = 1, estable = 1;
    static uint32_t instante_cambio = 0;

    if (lectura != ultima) {
        ultima = lectura;
        instante_cambio = ms;
    }
    if ((uint32_t)(ms - instante_cambio) >= 30U &&
        estable != ultima) {
        estable = ultima;
        return (estable == 0U);  // evento de presión
    }
    return 0U;
}

El contador de milisegundos debe provenir de un temporizador. Una transición se acepta únicamente cuando la entrada permanece estable 30 ms. La función genera un evento al presionar; no requiere retardos bloqueantes.
